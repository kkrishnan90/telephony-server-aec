# Telephony Server-Side Acoustic Echo Canceller (Java)

A lightweight, zero-dependency Java library for server-side Acoustic Echo Cancellation (AEC) in real-time telephony audio pipelines. It is designed to sit between an 8 kHz telephony gateway (RTP, SIP media forking, G.711 u-law/A-law, or linear PCM) and a downstream conversational AI voice model or speech recognition engine (16 kHz input / 24 kHz output).

## Overview

When a caller interacts with an automated voice agent over a telephony trunk using a speakerphone or an imperfectly isolated handset, the outbound agent voice (far-end reference) leaks back into the caller's microphone (near-end capture) after a variable network and jitter buffer delay. Without server-side echo cancellation, the echoed agent audio can cause false voice activity detection (self-interruption) or degrade speech recognition accuracy when the caller speaks over the agent (double-talk).

This library runs on the backend server and provides:

1. **1st-Order High-Pass DC Blocker:** Removes PSTN and G.711 DC bias and low-frequency hum below 80 Hz.
2. **Bulk Network Delay Estimator:** Automatically tracks and aligns variable round-trip gateway and jitter buffer delays (up to 240 ms by default, configurable up to 1000 ms) using smoothed cross-correlation over a far-end reference ring buffer.
3. **Normalized Least Mean Squares (NLMS) Adaptive FIR Filter:** Models the linear acoustic and hybrid echo impulse response and subtracts predicted echo from the inbound caller audio.
4. **Geigel and Residual Coherence Double-Talk Detector (DTD):** Detects when a caller barges in while the agent is speaking, immediately freezing adaptive filter weights so the caller's voice does not corrupt the echo model and preserving caller speech clarity.
5. **Non-Linear Processor (NLP) and Comfort Noise Generator (CNG):** Attenuates residual non-linear G.711 quantization and speakerphone distortion during far-end single-talk while maintaining a natural background noise floor.
6. **Built-In Telephony Codecs and Resamplers:** Includes ITU-T G.711 u-law (PCMU) and A-law (PCMA) codecs, 24 kHz to 8 kHz anti-aliased FIR decimation (3:1), 16 kHz to 8 kHz decimation (2:1), and 8 kHz to 16 kHz cubic interpolation (1:2).

## Prerequisites

* **Java Development Kit (JDK):** Java 11 or higher (tested with OpenJDK 11, 17, 21, and 26).
* **External Dependencies:** None. The library uses only standard `java.base` classes.
* **Build Tool (Optional):** Apache Maven 3.6+ or standard JDK tools (`javac` and `jar`) via the included `build.sh` script.

---

## Setup Note

For effective server-side echo cancellation, the AEC instance must observe both directions of the same call session:

1. **Outbound Reference Stream (Far-End):** Audio generated by the voice model or TTS engine before or as it is sent to the telephony gateway.
2. **Inbound Capture Stream (Near-End):** Audio arriving from the caller's telephony leg before it is forwarded to the voice model.

Always use one `AcousticEchoCanceller` instance per call leg (or pass a unique `callId` to `TelephonyAecPipelineService`, which manages thread-safe per-call state automatically).

## Installation

### Option 1: Build from Source (No Maven Required)

Clone the repository and run the build script using standard JDK tools:

```bash
git clone https://github.com/kkrishnan90/telephony-server-aec.git
cd telephony-server-aec
./build.sh
```

This compiles the library targeting Java 11 bytecode, runs all unit and functional tests, and generates the distributable artifacts in `dist/`:

* `dist/telephony-server-aec-1.0.0.jar`
* `dist/telephony-server-aec-1.0.0-sources.jar`

### Option 2: Build and Install with Maven

```bash
mvn clean install
```

Then include the dependency in your application's `pom.xml`:

```xml
<dependency>
    <groupId>com.telephony</groupId>
    <artifactId>telephony-server-aec</artifactId>
    <version>1.0.0</version>
</dependency>
```

### Option 3: Direct JAR Dependency (Gradle or Classpath)

Copy `dist/telephony-server-aec-1.0.0.jar` into your project's `libs/` directory:

```groovy
// build.gradle
dependencies {
    implementation files('libs/telephony-server-aec-1.0.0.jar')
}
```

## Usage

### 1. Multi-Call Pipeline Service (Recommended for Server Backends)

Use `TelephonyAecPipelineService` in your WebSocket or RTP media server to manage concurrent call sessions. Hook into the outbound model audio path and the inbound caller audio path right before sending audio to the model:

```java
import com.telephony.aec.AecConfig;
import com.telephony.aec.TelephonyAecPipelineService;
import com.telephony.aec.TelephonyAecPipelineService.ProcessedFrame;

public class AudioPipelineExample {

    private final TelephonyAecPipelineService aecPipeline = new TelephonyAecPipelineService();

    public void onCallStarted(String callId) {
        AecConfig config = AecConfig.builder()
                .sampleRateHz(8000)
                .frameSizeSamples(160)       // 20 ms frame at 8 kHz
                .filterLengthSamples(512)    // 64 ms adaptive FIR tail
                .maxBulkDelayMs(240)         // Up to 240 ms network/jitter delay alignment
                .nlmsStepSize(0.40)
                .nlpEnabled(true)
                .build();
        aecPipeline.registerCallSession(callId, config);
    }

    // Hook 1: Called when the AI voice model emits 24 kHz PCM16LE outbound audio
    public void handleModelOutboundAudio(String callId, byte[] modelPcm24kHzLe) {
        // Downsamples 24 kHz -> 8 kHz, records far-end reference for AEC,
        // and returns 8 kHz PCM16LE (or use onOutboundModelAudio24kHzToUlaw for G.711 u-law)
        byte[] telephonyOutbound8kHz = aecPipeline.onOutboundModelAudio24kHz(callId, modelPcm24kHzLe);
        sendToTelephonyGateway(callId, telephonyOutbound8kHz);
    }

    // Hook 2: Called when a 20 ms 8 kHz frame arrives from the telephony gateway
    public void handleCallerInboundAudio(String callId, byte[] callerPcm8kHzLe) {
        // Cancels echo and upsamples clean audio from 8 kHz -> 16 kHz PCM16LE
        ProcessedFrame processed = aecPipeline.onInboundCallerAudio8kHz(callId, callerPcm8kHzLe);

        // Send the echo-cancelled 16 kHz PCM16LE bytes to the downstream voice model
        byte[] clean16kHzForModel = processed.getClean16kHzPcmLe();
        sendToVoiceModel(callId, clean16kHzForModel);

        // Optional: inspect per-frame telemetry
        if (processed.getAecResult().isBargeInTriggerRecommended()) {
            // Caller is speaking over the agent
        }
    }

    public void onCallEnded(String callId) {
        aecPipeline.closeCallSession(callId);
    }

    private void sendToTelephonyGateway(String callId, byte[] audio) {}
    private void sendToVoiceModel(String callId, byte[] audio) {}
}
```

### 2. G.711 u-law (PCMU) RTP Pipeline Integration

If your telephony gateway exchanges raw 8-bit ITU-T G.711 u-law RTP payloads (160 bytes per 20 ms packet):

```java
// Outbound: 24 kHz PCM16LE from model -> 8 kHz G.711 u-law for telephony RTP
byte[] outboundUlaw = aecPipeline.onOutboundModelAudio24kHzToUlaw(callId, modelPcm24kHzLe);

// Inbound: 8 kHz G.711 u-law from telephony RTP -> Echo-cancelled 16 kHz PCM16LE for model
ProcessedFrame frame = aecPipeline.onInboundCallerG711Ulaw(callId, inboundUlawPacket);
byte[] clean16kHzPcmLe = frame.getClean16kHzPcmLe();
```

### 3. Direct Single-Session API with Arbitrary Streaming Chunk Sizes

If your pipeline receives non-frame-aligned byte chunks over a stream, `AcousticEchoCanceller` provides internal byte framing buffers:

```java
import com.telephony.aec.AcousticEchoCanceller;
import com.telephony.aec.AecConfig;

AcousticEchoCanceller aec = new AcousticEchoCanceller(AecConfig.defaults());

// Feed arbitrary-length 8 kHz PCM16LE far-end reference bytes as they go out
aec.feedFarEndReference8kHzPcmLe(outbound8kHzChunk);

// Process arbitrary-length inbound 8 kHz PCM16LE bytes and receive clean 16 kHz PCM16LE bytes
byte[] clean16kHzChunk = aec.processInboundStreamTo16kHzPcmLe(inbound8kHzChunk);
```

## Expected Input and Output

### Audio Input Specifications

| Direction | Supported Formats | Sample Rate | Standard 20 ms Frame Size |
| :--- | :--- | :--- | :--- |
| **Outbound Reference (Model to Telephony)** | 16-bit Signed Little-Endian Mono PCM (`PCM16LE`) | 24,000 Hz or 8,000 Hz | 960 bytes (480 samples at 24 kHz) or 320 bytes (160 samples at 8 kHz) |
| **Inbound Capture (Telephony to Model)** | `PCM16LE`, ITU-T G.711 u-law (`PCMU`), or ITU-T G.711 A-law (`PCMA`) | 8,000 Hz | 320 bytes (`PCM16LE`) or 160 bytes (`PCMU` / `PCMA`) |

### Audio and Telemetry Output Specifications

Each processed 20 ms frame returns a `ProcessedFrame` / `AecFrameResult` containing:

| Output Method | Type | Description |
| :--- | :--- | :--- |
| `getClean16kHzPcmLe()` | `byte[]` (640 bytes / 320 samples) | Echo-cancelled, upsampled 16 kHz 16-bit little-endian mono PCM ready for model input (`audio/pcm;rate=16000`). |
| `getClean8kHzPcmLe()` | `byte[]` (320 bytes / 160 samples) | Echo-cancelled 8 kHz 16-bit little-endian mono PCM at native telephony rate. |
| `getErleDb()` | `double` | Smoothed Echo Return Loss Enhancement (ERLE) in decibels (dB). Values of 18 dB to 40+ dB indicate strong echo suppression. |
| `getEstimatedBulkDelayMs()` | `int` | Estimated round-trip network and gateway bulk delay in milliseconds (in 20 ms increments). |
| `isFarEndActive()` | `boolean` | `true` when the outbound agent reference signal is actively speaking at the aligned delay. |
| `isNearEndSpeechActive()` | `boolean` | `true` when caller speech is present after echo cancellation. |
| `isDoubleTalkDetected()` | `boolean` | `true` when caller speech overlaps with active far-end agent audio (filter adaptation frozen). |
| `isBargeInTriggerRecommended()` | `boolean` | `true` when verified caller speech interrupts active agent playback. |
